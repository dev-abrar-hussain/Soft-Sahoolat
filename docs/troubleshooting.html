Troubleshooting.

Start with the Dashboard status and WooCommerce logs, then work through the matching symptom below.

Feed URL returns 404

  1. Confirm the channel is enabled.
  2. Activate a valid license and select Regenerate Now.
  3. Open Settings → Permalinks and save once to refresh rewrite rules.
  4. Confirm wp-content/uploads/wc-feeds/ is writable by PHP.
  5. Exclude /wc-feeds/ from security or caching rules that replace the response.

Generation is already running

WooFeeds Pro uses a database-backed lock to stop two catalog jobs from writing the same feed. Wait for the active job. A stale lock older than 30 minutes is recovered automatically on the next attempt.

Feed generation failed

Open WooCommerce → Status → Logs and select the log source containing woofeeds-pro. Common causes include:

  • the uploads directory is not writable;
  • PHP ran out of memory;
  • zlib is missing for ChatGPT compression; or
  • a third-party product extension returned an unexpected value.

On memory-limited hosting, lower the batch size from the Field Mapping tab.

ChatGPT feed cannot be created

Confirm the PHP zlib extension is enabled and gzopen is available. Also verify seller name, store country and at least one target country.

Validation reports missing brand, GTIN or MPN

Open Field Mapping and choose the actual WooCommerce attribute or custom field used by the store. Mapping a source does not create missing data; edit the affected products after mapping.

Products or variations are missing

  • Only published products are considered.
  • A product must be purchasable, or be an external product.
  • Only visible purchasable variations are exported.
  • Regenerate after changing product visibility or status.

Scheduled feeds do not refresh

WP-Cron depends on site traffic unless a system cron triggers it. Use one of these approaches:

wp cron event run woofeeds_pro_generate_feeds --due-now

wp woofeeds generate

When using a real cron, call the command at least as often as the refresh interval selected in WooFeeds Pro.

License server is unreachable

  1. Confirm the API URL starts with HTTPS and has no endpoint suffix.
  2. Open the License tab and select Check Now.
  3. Check outbound HTTPS access from WordPress.
  4. Verify the license service's /health endpoint.
  5. If the service is temporarily down, confirm the last successful validation still falls within grace.

License is active on another domain

Deactivate the old installation first. www. and the apex domain are treated as one host, but staging subdomains remain separate and require the old activation to be cleared.

Channel imported an old snapshot

Compare the feed's Last-Modified response and the Dashboard generation time. The public endpoint uses ETags and a one-hour cache policy. The channel may also have its own fetch schedule and processing delay.
